# EdoConnectorMock: XSLT-трансформация электронных транспортных накладных (ЭТрН)

Консольное приложение на **C#**, демонстрирующее работу middleware-коннектора для обмена электронными документами. Проект имитирует реальный кейс интеграции учетной системы клиента (ERP) с платформой оператора ЭДО.

## 📌 Описание задачи
Учетная система клиента генерирует данные о грузоперевозках в нестандартном (кастомном) XML-формате. 
**Цель:** С помощью `XSLT` и `XPath` распарсить этот файл, извлечь необходимые узлы, отформатировать типы данных и пересобрать XML в строгий формат, соответствующий требованиям ГИС ЭПД (Государственная информационная система электронных поездных документов) и операторов ЭДО.

## 🛠 Технологии
*   **C# / .NET** (Использование класса `XslCompiledTransform` для обработки XML).
*   **XML / XSLT 1.0** (Декларативное описание правил трансформации).
*   **XPath** (Навигация по DOM-дереву документа).

## ⚙️ Что реализовано в XSLT-скрипте:
1.  **Конкатенация строк:** Динамическое формирование уникального атрибута `ИдФайл` на основе номера заказа (`OrderNumber`).
2.  **Работа с подстроками (Substrings):** Парсинг и реверсирование сырой даты из формата `ДД.ММ.ГГГГ` в строгий стандарт `ГГГГ-ММ-ДД`.
3.  **Реструктуризация DOM-дерева:** Перенос значений из XML-элементов клиентского файла (например, `Cargo/Description`) в XML-атрибуты финального документа (`<Груз Описание="...">`), как того требует спецификация ФНС.

## 🚀 Как запустить
1. Клонировать репозиторий.
2. Открыть решение `.sln` в Visual Studio.
3. Убедиться, что для файлов `input.xml` и `transform.xslt` в свойствах установлено `Copy to Output Directory = Copy if newer`.
4. Запустить проект (F5). Результат преобразования будет сохранен в `output.xml` и выведен в консоль.
